# 用 Alexa 问答采集拿真实买家问题

买家会问什么，不要靠编。Alexa 购物助手（原 Rufus）照着评论回答问题，把问题批量问过去，拿回来的就是买家真正关心的点，以及同类产品在哪儿翻车。

工具：amazon-alexa-insight（开源，github.com/WaytoAIC/amazon-alexa-insight），命令行叫 apinsight。没装或跑不通时看最后一节，照常往下做。

## 两种用法，别混

| 用法 | 问谁 | 用哪套题 | 结果填进哪 |
|---|---|---|---|
| 摸买家关心什么 | 3 到 5 个竞品 | 工具内置题库 | buyer_questions、review_insights、competitor_insights |
| 验自己答没答上 | 自己的商品（要已上架） | 必答问题表导出的文件 | 模块 30 的「实际由哪句回答」和判定 |

## 怎么跑

先自检，再采集：

```
node bin/apinsight.js doctor --json
node bin/apinsight.js collect --asins <编号,编号> --questions summary_all
```

- doctor 的 blockers 里 needsHuman 为 true（要登录、撞验证码）时，停下来告诉用户，不要替用户登录，不要填验证码。
- 结果在 run 目录的 CSV 里，列是：商品编号、标题、价格、类目、问题、回答、英文回答、状态、时间。只取状态正常的行。
- 问自己的商品时，把必答问题表的「问题」列按站点语言每行一题存成文件，把 `--questions` 换成那个文件路径。
- 限速用工具默认值，不要调快。

## 拿回来的东西怎么用

- Alexa 的回答是它对评论的转述，不是厂家给的事实：一律按「待核实」处理，不能直接抄进文案。
- 竞品的回答只说明买家在意什么、同类产品什么地方出问题，不能当自家产品的事实。
- 回答里反复出现的抱怨进 review_insights.pains，买家反复问的进 buyer_questions。
- 问自己的商品时，Alexa 答不上来或者答错了，说明 Listing 这块没写清楚，记进「上架前待办」。
- 文案里写过的宣称，Alexa 会当成事实转述给买家，还会自己往下发挥。所以没依据的话一个字都不能写——不是洁癖，是它会被放大成一句你担不起的承诺。

## 跑不了的时候

没装工具、没有可用买家号、撞了验证码没人处理，都照常往下做：用户给的实采问答和评论优先，不够的方面才自己补问题并标来源「模拟」，同时在「上架前待办」里记一条「必答问题未经实测」。
