# 00 买家必答问题表

写文案之前，先定好“这份 Listing 必须答得上哪些问题”。买家和 Alexa 购物助手（原 Rufus）都只认 Listing 里明确写出来的信息。先知道会被问什么，再去写；不要写完才检查。

## 用到的字段

buyer_questions、review_insights、competitor_insights、usps、specs、compatibility、package_contents、certifications、not_suitable_for、variation_family

## 做法

1. 收问题，按来源排先后：实测 > 实采 > 评论 > 模拟。实测 = 拿 Alexa 问答采集工具问竞品拿回来的，优先走这条，做法见 references/alexa-insight.md；实采 = 买家真实问过的原话（用户给的 Alexa 问答、商品页上的 Ask Alexa 模块、竞品页面的问答、客服记录）；评论 = 从评论内容里归纳出来的疑问；模拟 = 你自己补的。前三种来源的问题全部保留。
2. 把下面这些方面补齐，每个方面至少 1 条，合计不少于 20 条：是什么和含什么、规格尺寸、材质做工、兼容适配、使用和安装、清洁维护、安全和认证、适合谁和不适合谁、和同类的差别、售后；有变体时再加“变体怎么选”。前三种来源覆盖不到的方面，才自己补模拟题。
3. 问题写成买家会说的完整问句，不写关键词，用目标站点的语言写——这一列要能整列导出去直接问 Alexa。
4. 逐条对照事实字段，填“有无依据”：有 / 部分 / 无。
   - 部分：只回答有依据的那部分，其余记进「上架前待办」（补资料）。
   - 无：“计划放哪”填“不写”，“判定”填“不写”，同时记进「上架前待办」（补资料）。写文案时不回答、也不暗示这类问题。
   - 只有待核实的依据：按“无”处理，记进「上架前待办」（核实）。
5. 给有依据的问题填“计划放哪”，只从这几个里选，可以多选：标题 / Item Highlights / 五点 / 描述 / A+ / 后台属性 / 图片 / 视频。差评里的高频问题优先放五点前三条。
6. 优先级：实测、实采和高频差评 = 高；评论里偶尔出现 = 中；模拟 = 低。「来源」列照实写实测 / 实采 / 评论 / 模拟。

## 产出

交付模板的「必答问题表」，此时只填前六列。后两列“实际由哪句回答”“判定”留给 30-alexa-coverage-check.md。
