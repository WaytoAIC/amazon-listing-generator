# 00 Alexa 问答采集

买家会问什么、同类产品在哪儿翻车，不要靠编。Alexa 购物助手（原 Rufus）照着评论回答问题，把问题批量问过去，拿回来的就是现成答案。

工具：**amazon-alexa-insight**，Chrome 插件和命令行两种形态，仓库 https://github.com/WaytoAIC/amazon-alexa-insight

## 两种用法，别混

| 用法 | 问谁 | 用哪套题 | 结果填进哪 |
|---|---|---|---|
| 摸买家关心什么 | 3 到 5 个竞品 | 工具内置题库 | buyer_questions、review_insights、competitor_insights |
| 验自己答没答上 | 自己的商品，要已上架 | 必答问题表导出的文件 | 模块 30 的「实际由哪句回答」和判定 |

## 三条路，按顺序试

1. **用户手上已有导出文件**——先问这一句。让用户把文件放进工作目录，直接读。这条最省事，也不占用户的买家号额度。插件和命令行导出的 CSV / Excel / JSON 共用一套列名，是英文的，照抄不要翻译：

   `ASIN`、`Product Title`、`Price`、`Category`、`Question`、`Answer`、`Answer (EN)`、`Status`、`Timestamp`

   三个坑：CSV 带 BOM，按 `utf-8-sig` 读；回答里有换行，必须用 CSV 解析器，不能按行数当条数；JSON 的数据在 `results` 键下面，不是顶层数组。
   `Status` 不正常的行，回答不要用，但问题本身照样收进必答问题表——工具超时说明的是没问到，不是这个问题不重要。
2. **本机装了命令行**。先自检 `node bin/apinsight.js doctor --json`；blockers 里 needsHuman 为 true（要登录、撞验证码）就停下来告诉用户，不要替用户登录，不要填验证码。能跑就 `collect --asins <编号,编号> --questions summary_all`。问自己的商品时，把 `--questions` 换成必答问题表导出的文件路径（每行一题，按站点语言写）。限速用默认值，不要调快。
3. **两样都没有**：把上面的仓库地址给用户，说明装插件就能自己采，然后照常往下做，见最后一节。

## 拿回来的东西怎么用

- Alexa 的回答是它对评论的转述，不是厂家给的事实：一律按「待核实」处理，不能直接抄进文案。
- 竞品的回答只说明买家在意什么、同类产品什么地方出问题，不能当自家产品的事实。
- 回答里反复出现的抱怨进 review_insights.pains，买家反复问的进 buyer_questions。
- 几个竞品一起抱怨同一件事，那是类目通病，不是某一家的毛病，值得单独拎出来。要是这条通病正好是本品的核心卖点（比如薄，既是「扫地机器人能开上去」也是「站着硌脚」），就必须在五点里主动划清边界、说明不适合谁——躲着不谈，买家照样会在差评里替你说。
- 问自己的商品时，Alexa 答不上来或者答错了，说明 Listing 这块没写清楚，记进「上架前待办」。
- 文案里写过的宣称，Alexa 会当成事实转述给买家，还会自己往下发挥。所以没依据的话一个字都不能写——不是洁癖，是它会被放大成一句你担不起的承诺。

## 采不到的时候

没工具、没导出文件、没有可用买家号、撞了验证码没人处理，都照常往下做：用户给的实采问答和评论优先，不够的方面才自己补问题并标来源「模拟」，同时在「上架前待办」里记一条「必答问题未经实测」。

## 产出

填好 buyer_questions、review_insights、competitor_insights；把用到的导出文件或 run 目录记进 data_sources.alexa_insight，方便回溯。
