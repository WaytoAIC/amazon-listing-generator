# 30 Alexa 问答覆盖验证（原 Rufus 问答验证）

写完之后，回到必答问题表，验证这份 Listing 是不是真的答上了。判断标准不是回答好不好看，而是：只凭 Listing 里明确写出的文字和属性，能不能给出确定、不含推断的回答。

## 用到的字段

must_answer，以及被检查的标题、Item Highlights、五点、描述、Search Terms、后台属性表和 A+ 需求单里的文案

## 做法

1. 没有必答问题表，就先按 00-must-answer-questions.md 建一张。
2. 逐条扮演 Alexa 购物助手作答：只许引用或复述 Listing 里明确存在的信息，不用常识补完。
3. 填后两列：
   - 实际由哪句回答：写出位置和原句，如“Bullet 2：Holds 32 oz …”
   - 判定：已覆盖 / 部分覆盖 / 未覆盖
4. 有依据却“未覆盖”或“部分覆盖”的，回到计划放的那个位置补写，只补这一次；补完重新判定。用户说先不改文案时跳过这一步，只报告。
5. “有无依据”为“无”的问题：确认文案既没有回答、也没有暗示；“实际由哪句回答”留空，判定填“不写”。检查别人写好的旧稿时，如果旧文案回答了这类问题，把那句话照实填上；脚本会把它标成不通过，这正是要报告的问题。
6. 仍然答不上的，连同缺的字段或参数，记进「上架前待办」（补资料）。这就是下一轮改进的清单。
7. 用户给过真实的 Alexa 问答时，把模拟判定和实采表现不一致的地方单独列出来。

## 产出

补全交付模板「必答问题表」的后两列；再写一句覆盖结论（多少条有依据，覆盖了多少），放在表的下面，同时在对话里说。
