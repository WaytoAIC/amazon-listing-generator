# Module Prompts

## 使用原则

- 只读取当前任务需要的模块章节。
- 先完成输入归一化，再按模块骨架组织提示。
- 只要任务涉及标题、Item Highlights、五点或 Search Terms，先做第 0 节“关键词四层分配”，再动笔。
- 如果用户要求“整套输出”，按文末列出的固定顺序依次执行。

## MCP 联动总规则

- 如果系统接了 Sorftime、卖家精灵等 Amazon 数据 MCP，且用户没有给足关键词、竞品、评论或类目资料，先做数据补强。
- 关键词类数据先喂给关键词四层分配，再按分配结果进入标题、Item Highlights、五点、Search Terms、A+ 和视频脚本。
- 竞品结构类数据优先喂给标题、主附图 Brief、A+ 和现有 Listing 改写。
- 评论与问答类数据优先喂给五点、图片、视频脚本和 Rufus 验证。
- 市场与类目定位类数据优先喂给标题措辞、卖点排序和 A+ 价值主张。
- 任何销量、BSR、PPC、点击率、评论比例等数据只用于内部决策，不直接写进面向买家的文案。

## 0. 关键词四层分配（前置步骤）

不算输出模块。先给每个词分配位置，再动笔，不要把词都塞进标题。

### 适用场景

- 全套生成的第一步
- 单独生成标题、Item Highlights、五点或 Search Terms 之前
- 把超过 75 字符的旧标题拆成“标题 + Item Highlights”之前

### 必填输入

- `keyword_pool`
- `product_name`
- `usps`
- `specs`
- `keyword_evidence` 可选，用户自带或 MCP 跑出来的搜索量、流量数据，用来排序

### 输出格式

- Markdown 表格
- 列固定为：词、热度或优先级、去哪、理由
- “去哪”只能填：标题 / Item Highlights / 五点与 A+ / Search Terms / 不用（写明原因）

### 分配规则

| 层 | 放什么词 | 去哪 |
|---|---|---|
| 1 | 核心产品词：定义“这是什么产品” | 标题 |
| 2 | 功能属性词、材质特点词 | Item Highlights |
| 3 | 使用场景词、购买理由词 | 五点 / A+ |
| 4 | 长尾词、同义词、拼写变体 | Search Terms |

### 硬性规则

- 分配单位是关键词池里的整条关键词；一条关键词只进一个位置，不重复堆砌
- 先按词的性质定层，热度只决定同一层里谁先上
- “修饰 + 中心词”的复合关键词（如 stainless steel water bottle）这样定层：热度最高、最能说清“这是什么”的那条整条进标题；其余的看修饰部分，是材质或功能就归 Item Highlights，是场景就归五点
- 多条关键词共用的中心词（如 water bottle）在标题出现一次即可，其他位置只写各自独有的部分（如 stainless steel、with straw）
- 标题放不下时，把热度低的挪到 Item Highlights；标题放下品牌、核心产品名和关键变体属性后还有余量时，可以按热度把 Item Highlights 层的词补进标题，以读着自然为准，补进标题的词不再进 Item Highlights
- 可读性优先于覆盖率
- 没有热度数据时按与产品的贴合程度排，并注明“无数据，按相关性判断”
- 禁用词标“不用”并写明原因；品牌词、竞品词只剔除品牌部分，剩下的通用词照常分配
- 产品资料里找不到依据的宣称类词（例如资料没写防漏，词池里却有 leak proof）也标“不用”，前台和 Search Terms 都不放，并提醒用户确认
- 分配表随最终产出一起交付；后面各模块要埋的搜索词只用分给自己的那部分

### 提示词骨架

```text
【角色】
你是亚马逊关键词规划专家。

【输入】
- 产品名(品类词): {product_name}
- 核心卖点/差异点: {usps}
- 关键参数: {specs}
- 关键词池: {keyword_pool}
- 关键词证据(可选): {keyword_evidence}
- 禁用词/限制: {banned_terms}

【任务】
把关键词池里的每个词分配到唯一位置：
- 核心产品词(定义“这是什么产品”) → 标题
- 功能属性词、材质特点词 → Item Highlights
- 使用场景词、购买理由词 → 五点 / A+
- 长尾词、同义词、拼写变体 → Search Terms
- 禁用词、产品资料里找不到依据的宣称类词 → 不用（写明原因）
- 含品牌或竞品品牌的词 → 只剔除品牌部分，剩下的通用词照常分配
一条关键词只进一个位置；先按词的性质定层，热度只决定同一层里谁先上；可读性优先于覆盖率。

【输出】
仅输出分配表：词 | 热度或优先级 | 去哪 | 理由
```

## 1. 标题

### 新规要点

- 2026-07-27 起，标题不得超过 75 字符，含空格、标点和品牌名。
- 适用于所有商品类型，媒体类除外；沙特、埃及、土耳其、阿联酋站点不适用。
- 超长或不合规的标题，亚马逊可能用 AI 自动改写，或不在搜索结果中显示；品牌备案卖家在改写生效前有 14 天审阅期。
- 标题的作用是定义商品身份，回答“这是什么产品”，不是堆关键词。放不下的属性交给 Item Highlights。

### 适用场景

- 从零生成标题
- 重写标题
- 把超过 75 字符的旧标题压到合规，多出来的信息转给 Item Highlights
- 做移动端优先标题优化

### 必填输入

- `country_site`
- `language`
- `product_name`
- `brand` 可选
- `usps`
- `specs`
- `keyword_allocation` 中分给标题的词
- `banned_terms`

### 输出格式

- 输出 2 行：第 1 行是标题，第 2 行写“字符数：N”（含空格）
- 不超过 75 字符
- 不受新规限制的站点或媒体类商品，按该类目风格指南的长度执行，仍以简洁为先

### 硬性规则

- 结构：品牌（如有）+ 核心产品名 + 关键属性；无品牌时直接以品类主词开头
- 要埋的搜索词只用关键词分配表里分给标题的词；品牌、变体属性和关键参数照常取自产品事实
- 最重要的变体属性（颜色、尺寸、件数）放标题，其余交给 Item Highlights
- 放不下时的取舍顺序：先保品牌和核心产品名，再保区分变体的那一两个属性，最后才是其余分给标题的词；挪出去的按热度从低到高进 Item Highlights
- 同一个词最多出现 2 次，介词、冠词和连词除外
- 不用这些字符：`! $ ? _ { } ^ ¬ ¦`；其他符号不作装饰用
- 不写促销语、主观词（如 Best Seller）、夸大词、医疗承诺和注册符号；不堆砌型号，只有类目风格指南要求时才写型号
- 用阿拉伯数字，不全大写，计量单位可缩写
- 可读性优先于关键词覆盖
- 输出前数一遍字符数，超了就删到达标

### 提示词骨架

```text
【角色】
你是亚马逊 SEO 标题优化专家。

【输入】
- 国家/站点: {country_site}
- 语言: {language}
- 产品名(品类词): {product_name}
- 品牌(可选): {brand}
- 核心卖点/差异点: {usps}
- 关键参数: {specs}
- 分给标题的词: {keyword_allocation.title}
- 禁用词/限制: {banned_terms}
- 参考竞品信息: {competitor_insights}
- 评论总结: {review_insights}

【核心理念】
标题的作用是定义商品身份，回答“这是什么产品”，不是堆关键词。

【任务】
生成 1 个适合 {country_site} 站的标题，不超过 75 字符（含空格、标点和品牌名），移动端一眼能看懂。

【输出】
第 1 行输出标题，第 2 行输出“字符数：N”。
```

## 2. Item Highlights

### 新规要点

- 随 75 字符标题新规一起推出的新字段，最多 125 字符。
- 显示在搜索结果和详情页的标题下方，内容可被搜索。
- 官方要求写成逗号分隔的短语，不写完整句子。
- 标题先改到 75 字符以内，才能添加 Item Highlights，所以标题必须先达标。
- 分工：标题回答“这是什么”，Item Highlights 回答“有什么优势”。

### 适用场景

- 从零生成 Item Highlights
- 把旧长标题里放不下的属性挪进 Item Highlights
- 检查现有 Item Highlights 是否和标题重复

### 必填输入

- `country_site`
- `language`
- `title` 已达标的标题
- `keyword_allocation` 中分给 Item Highlights 的词
- `usps`
- `specs`
- `banned_terms`

### 输出格式

- 输出 2 行：第 1 行是 Item Highlights，第 2 行写“字符数：N”（含空格和逗号）
- 逗号分隔的短语，不超过 125 字符
- 示例：`USB-C, PPS Supported, Cable Not Included`

### 硬性规则

- 要埋的搜索词只用关键词分配表里分给 Item Highlights 的词
- 产品事实里的材质、功能属性、关键参数和差异点也可以写，即使不在关键词池里（例如保冷 24 小时这类头号卖点）
- 不重复标题里已经出现的词，介词、冠词和连词除外
- 标题放不下的次要变体属性、兼容信息和包装内含物，可以放这里
- 每个短语都必须能在用户资料里找到依据
- 不写促销语、主观词、夸大词和医疗承诺
- 输出前数一遍字符数，超了就删短语，不要缩写到看不懂

### 提示词骨架

```text
【角色】
你是亚马逊 Listing 文案专家，熟悉 Item Highlights 字段。

【输入】
- 国家/站点: {country_site}
- 语言: {language}
- 已达标的标题: {title}
- 分给 Item Highlights 的词: {keyword_allocation.item_highlights}
- 核心卖点/差异点: {usps}
- 关键参数: {specs}
- 禁用词/限制: {banned_terms}

【核心理念】
标题回答“这是什么”，Item Highlights 回答“有什么优势”。

【任务】
生成 1 行 Item Highlights，不超过 125 字符，用逗号分隔的短语，不写完整句子，不重复标题里已有的词。

【输出】
第 1 行输出 Item Highlights，第 2 行输出“字符数：N”。
```

## 3. 五点

### 适用场景

- 从零生成 5 条五点
- 改写五点的转化层级
- 强化前两条移动端表现

### 必填输入

- `language`
- `audience_scenarios`
- `usps`
- `specs`
- `keywords_optional` 取 `keyword_allocation` 中分给五点的词
- `compliance_notes`

### 输出格式

- 严格输出 5 行
- 每行 1 条五点
- 前 2 条偏转化，后 3 条偏埋词与 Rufus 支撑

### 硬性规则

- 每条只讲 1 个主题
- 每条不超过 255 字符
- 尽量用动词开头
- 包含具体事实或数字
- 要埋的搜索词只用分配表里分给五点的使用场景词和购买理由词
- 关键词分配只管搜索词埋在哪，不限制写事实：材质、参数、兼容范围和使用限制该写就写，即使相关的词已经分给标题或 Item Highlights，否则 Rufus 答不上来
- 不整句照搬标题和 Item Highlights，不堆砌关键词
- 不允许医疗、极限词和无法证实的承诺

### 提示词骨架

```text
【角色】
你是亚马逊转化文案专家，熟悉移动端展示逻辑。

【输入】
- 语言/站点: {language}
- 用户人群/场景: {audience_scenarios}
- 核心卖点: {usps}
- 关键参数: {specs}
- 辅助关键词: {keywords_optional}
- 合规限制: {compliance_notes}
- 评论重点: {review_insights}

【任务】
生成 5 条五点。前 2 条承担转化，后 3 条承担索引、扩展语义和 Rufus 支撑。

【输出】
严格输出 5 行，每行 1 条五点。
```

## 4. Search Terms

### 适用场景

- 生成后台 Search Terms
- 在已有标题、Item Highlights 与五点基础上做未覆盖语义补位

### 必填输入

- `language`
- `country_site`
- `keyword_allocation` 中分给 Search Terms 的词
- `used_terms` 标题、Item Highlights 和五点里已经用过的词，三处都要算
- `semantic_buckets`

### 输出格式

- 输出 2 行：第 1 行是 Search Terms 字符串，第 2 行写“字节数：N”
- 总长度不超过 249 字节（官方要求少于 250 字节；超限有整段不被索引的风险，不要指望自动截断）

### 硬性规则

- 只用空格分隔
- 不要品牌词、竞品词、标点和重复词根
- 必须先按单词排除标题、Item Highlights 与五点中已使用的词
- 优先装关键词分配表里分给 Search Terms 的词：长尾词、同义词和拼写变体
- 还有空间时，按 `semantic_buckets` 补同义词和拼写变体；补的词必须和产品事实相符，不能带进资料里没有依据的功能
- 拼写变体指英美拼写、连写与分写（如 32oz）这类写法差异，不算重复词根
- 不用为了填满而硬凑，贴合度低的词宁可不放
- 分配表里标“不用”的词不放
- 不收常见错拼，亚马逊官方建议避免
- 输出前数一遍字节数，超了就整词删除，不要拆断词

### 提示词骨架

```text
【角色】
你是亚马逊后台关键词优化专家。

【输入】
- 语言/站点: {language}/{country_site}
- 分给 Search Terms 的词: {keyword_allocation.search_terms}
- 已使用词(标题 + Item Highlights + 五点): {used_terms}
- 需覆盖的语义域: {semantic_buckets}

【任务】
生成一条 Search Terms 字符串，长度不超过 249 字节，不与已使用词重复；还有空间时按语义域补同义词和拼写变体。

【输出】
第 1 行输出 ST 字符串，第 2 行输出“字节数：N”。
```

## 8. Rufus问答验证

### 适用场景

- 检查 Listing 是否覆盖高频购买疑问
- 发现 Rufus 无法稳定回答的缺口

### 必填输入

- `title`
- `item_highlights`
- `bullet_points`
- `description`
- `backend_terms`
- `usps_specs`

### 输出格式

- Markdown 表格
- 至少 20 条问题

### 硬性规则

- 问题必须是完整自然语言
- 覆盖功能、兼容、安装、维护、安全、差异、售后等维度
- 回答只能基于明确存在的信息
- 如果无法确定，必须明确写“无法回答”或“部分可回答”

### 提示词骨架

```text
【背景】
Rufus 不会猜测商品能力，只会基于 Listing 中明确存在的信息作答。

【角色】
你是一名亚马逊 Listing 质检官，从 Rufus 视角验证当前 Listing 的可回答性。

【输入】
- 产品标题: {title}
- Item Highlights: {item_highlights}
- 五点描述: {bullet_points}
- 产品描述: {description}
- Search Terms & 后台属性: {backend_terms}
- 卖点与规格: {usps_specs}

【任务】
生成不少于 20 条真实买家问题，并基于 Listing 信息模拟 Rufus 作答。

【输出】
以表格输出 Question、Answer、Confidence、Missing Info。
```

## 9. Listing自查

### 适用场景

- 做生成前后的合规审查
- 检查潜在违规、信息冲突和移动端问题

### 必填输入

- `title`
- `item_highlights`
- `images_info`
- `bullet_points`
- `description`
- `backend_keywords`
- `a_plus_content`

### 输出格式

- Markdown 表格
- 列固定为：模块、检查点、状态、问题说明、修改建议
- 表格后附一份宣称核对清单：宣称、用户资料里有无依据、处置

### 数值清单

| 模块 | 检查点 |
|---|---|
| 标题 | 不超过 75 字符，含空格、标点和品牌名（2026-07-27 新规；媒体类和沙特、埃及、土耳其、阿联酋站点除外）；超限可能被亚马逊 AI 自动改写或不在搜索结果中显示 |
| 标题 | 不含 `! $ ? _ { } ^ ¬ ¦`；同一个词不超过 2 次；无促销语（Best、Free Shipping、Cheapest）；无误导表述、竞品品牌或商家名；结构为品牌 + 核心产品名 + 关键属性 |
| Item Highlights | 不超过 125 字符；逗号分隔的短语，不是完整句子；不重复标题里已有的词；标题不超过 75 字符才能添加 |
| 五点 | 每条 10 到 255 字符；前两条承担转化；无医疗词和极限词 |
| 描述 | 不超过 2000 字符，HTML 标签计入 |
| 后台关键词 | 少于 250 字节，按不超过 249 字节检查；超限有整段不被索引的风险；无品牌名、竞品词和标点；不与标题、Item Highlights、五点重复 |
| 图片 | 主图纯白底 RGB(255,255,255)；产品约占画面 85%；无文字、水印和 Logo；最长边硬性范围 500 到 10000 像素，建议 1600 以上（官方建议至少 1000 才能缩放） |
| A+ | 建议有 500 字以上可被抓取的文本；图片有 alt-text；对比表用语义明确的属性名 |
| 整体一致性 | 逐条核对前台宣称能否在用户提供的事实里找到依据，列出所有找不到依据的宣称 |

### 硬性规则

- 必须检查标题、Item Highlights、图片、五点、描述、后台关键词、A+、整体一致性
- 长度类检查点必须写出实际数出来的字符数或字节数，不能只写“合规”
- 状态只用：合规 / 风险 / 违规
- 优先指出具体问题，不写空泛提醒

### 提示词骨架

```text
【角色】
你是一名亚马逊 Listing 合规审查官，熟悉 2026 年标题新规。

【输入】
- 标题: {title}
- Item Highlights: {item_highlights}
- 主图与附图: {images_info}
- 五点: {bullet_points}
- 产品描述: {description}
- 后台关键词: {backend_keywords}
- A+ 内容: {a_plus_content}

【任务】
对照数值清单逐项检查潜在违规、风险和信息不一致问题，写出实际长度，并给出修改建议。

【输出】
以表格输出：模块 | 检查点 | 状态 | 问题说明 | 修改建议
表格后附宣称核对清单：宣称 | 有无依据 | 处置
```
