# Amazon Listing Workflow

## 目的

把零散的产品资料、市场洞察和关键词信息，转换成一个同时服务用户与亚马逊系统的 Listing 产出流程。这个流程强调移动端优先、事实明确、Rufus 可回答和模块化交付。

## 什么是“好 Listing”

- 第一眼能看懂。用户先看标题、标题下方的 Item Highlights、主图、前 3 张图、前 2 条五点和 A+ 首屏。
- 双读者同时成立。文案既要让用户读得懂、信得过、敢下单，也要让亚马逊系统识别到正确属性与关键词。
- 前后台一致。前台表述、后台属性、Search Terms 和 Rufus 可回答内容不能互相矛盾。
- 移动端优先。默认按手机端体验设计信息密度、句长、视觉层级和图片构图。
- 图给用户，字给系统。图片主要承担快速理解与点击转化，文字承担解释、索引和问答支撑，但两者必须协同。

## 核心原则

### 1. 用户体验优先

- 当用户可读性和机械埋词冲突时，先保证用户一眼懂。
- 标题和五点前两条优先承接转化，不要被关键词堆砌破坏。
- 任何关键参数都尽量数字化、明确化，避免模糊词。

### 2. Rufus 视角

- Rufus 不会替卖家猜测产品能力。
- 只有 Listing 明确写出的信息，Rufus 才能稳定回答。
- 用户会问“具体是多少、支不支持、适不适配、怎么安装、有什么限制”这类问题，相关信息必须提前埋入文案或属性。

### 3. 信息先事实化，再文案化

- 原始输入先拆成事实字段，不要直接把素材原文丢给模块。
- 用户可能会问“具体是多少”的内容必须明确：尺寸、重量、兼容范围、功率、容量、材质、限制条件、认证、包装清单。
- 如果信息缺失会影响判断，先补阻塞项，再生成文案。

### 4. 标题定义身份，属性交给 Item Highlights

亚马逊 2026 标题新规（2026-07-27 起执行）：

- 标题不得超过 75 字符，含空格、标点和品牌名。适用于所有商品类型，媒体类除外；沙特、埃及、土耳其、阿联酋站点不适用。
- 新增 Item Highlights 字段，最多 125 字符，写成逗号分隔的短语，显示在搜索结果和详情页的标题下方，内容可被搜索。标题先改到 75 字符以内，才能添加。
- 超长或不合规的标题，亚马逊可能用 AI 逐步自动改写，或不在搜索结果中显示；品牌备案卖家在改写生效前有 14 天审阅期。

对写法的影响：

- 标题的作用是定义商品身份，回答“这是什么产品”，不再承担堆关键词的任务。
- Item Highlights 回答“有什么优势”，承接标题放不下的材质、功能属性和差异点，不重复标题里已有的词。
- 规则会变。拿不准时以亚马逊卖家后台帮助页“商品名称要求和指南”的最新内容为准。

## 输入准备 SOP

### 1. 产品素材收集

至少整理以下信息：

- 站点、语言、品类、产品名、品牌
- 规格参数：尺寸、重量、容量、承重、功率、兼容范围、不适配范围
- 结构与材质：材质、工艺、核心结构、使用限制
- 包装清单：配件、说明书、适配器、线材、收纳、安装件
- 认证与合规：测试报告、认证、专利、注意事项
- 卖点与差异点：用户为什么选它，不选替代方案
- 风险点：常见误用、兼容性风险、限制条件、售后边界

### 2. 市场调研

竞品选择不要只看销量，要覆盖不同定位：

- BSR 头部
- 高评分 / 高销量
- 高价位 / 低价位
- 风格明显不同
- 同适配型号或同核心场景

竞品调研重点不是“谁卖得好”，而是：

- 他们把什么信息放在第一眼
- 主图、前几张附图分别承担什么信息
- 标题和前两条五点在强调什么
- 有没有把用户高频问题提前前置

### 3. 评论分析

评论分析重点看反复出现的问题类型，而不是只看比例：

- 用户不满意什么
- 用户原本期待什么
- 用户容易怎么用错
- 哪些兼容性或限制信息最容易引发误解

### 4. 关键词分析

关键词的目的不是简单“选词”，而是先给每个词分配一个位置，再动笔。这一步叫关键词四层分配：

- 核心产品词（定义“这是什么产品”）：标题
- 功能属性词、材质特点词：Item Highlights
- 使用场景词、购买理由词：五点和 A+，图 2、图 3 与视频脚本沿用同一批词
- 长尾词、同义词、拼写变体：Search Terms

一条关键词只进一个位置，不重复堆砌；先按词的性质定层，热度只决定同一层里谁先上，可读性优先于覆盖率。资料里找不到依据的宣称类词不分配。关键词分配只管搜索词埋在哪，不限制五点写材质、参数这类事实。

分析时至少拆这几个维度：

- 意图：功能 / 场景 / 人群 / 兼容 / 痛点
- 强度：高 / 中 / 低
- 竞争：强 / 中 / 弱
- 价值：高 / 中 / 低

### 5. MCP 数据补强

当系统已接入 Sorftime、卖家精灵或其他 Amazon 数据 MCP，且用户没有给出足够完整的关键词、竞品、评论或类目资料时，先补强再起草。

优先补强这些信息：

- 关键词池与语义分层：主词、转化词、长尾词、兼容词、场景词
- 竞品前置信息：竞品标题前半段、前两条五点、前 3 张图强调点
- 评论痛点与误用：高频负评、兼容性问题、安装误解、用户期待
- 类目与定位：价格带、核心对手、类目主流表达、差异化空间
- 流量与问答线索：高频流量词、Rufus 可能被问到的问题方向

使用边界：

- MCP 数据优先用于内部判断和排序，不直接写成前台卖点事实。
- 用户自有资料、品牌资料、包装清单、官方规格仍然是事实源的最高优先级。
- 竞品销量、BSR、PPC、点击率、评论比例等数据可以指导“先写什么”，但不能直接变成“消费者可见承诺”。
- 如果 MCP 给出的商品详情与用户资料冲突，先指出冲突，再以用户确认结果为准。

## 生成顺序

默认按下面顺序生成：

0. 关键词四层分配（前置步骤，不算模块）
1. 标题
2. Item Highlights
3. 五点
4. Search Terms
5. 主附图设计需求
6. A+设计需求
7. 视频脚本
8. Rufus问答验证
9. Listing自查

这个顺序的原因：

- 关键词四层分配先定每个词去哪，避免各模块抢词或重复
- 标题先定商品身份与搜索入口
- Item Highlights 必须在标题达标之后写，并且不重复标题
- 五点承接转化与信息展开
- Search Terms 依赖标题、Item Highlights 与五点，避免重复词根
- 图片、A+、视频继续承接同一套卖点逻辑
- Rufus 验证用于检查“可回答性”
- Listing 自查用于检查“合规性和一致性”

## 现有 Listing 优化流程

当用户提供已有 Listing 草稿时：

1. 先抽取现有标题、Item Highlights、五点、描述、Search Terms、图片信息、A+ 信息
2. 判断缺口：标题是否超过 75 字符、有没有 Item Highlights、事实不完整、关键词缺口、转化层级问题、Rufus 无法回答、潜在违规
3. 只改用户要求的模块，保留能复用的既有有效信息
4. 如果旧标题超过 75 字符，先做关键词四层分配，再拆成“合规标题 + Item Highlights”，旧标题里的信息尽量不丢
5. 如果改动 Search Terms，先重新识别标题、Item Highlights 和五点中已使用词

## 质量检查清单

- 是否一眼能看懂产品是什么
- 标题是否不超过 75 字符，Item Highlights 是否不超过 125 字符且不重复标题
- 是否每条关键词只分配到一个位置
- 是否把最重要的差异点放到了最前面
- 是否把关键数字写清楚
- 是否存在前后台矛盾
- 是否存在 Rufus 无法回答的高频问题
- 是否存在合规高风险表述
- 是否在移动端依然清晰
