# 变体族怎么处理

只在 variation_family 不为空时读。评论共享、搜索展示等平台规则，读 platform-rules.md 的「变体」和「标题」两节。

## 总原则

- 默认只出一份基础 Listing 加一张「变体差异表」，不为每个子体各写一整套。用户明确要每个子体各一套时再展开。
- 基础 Listing 的文案小节写父体：标题不带颜色和尺码；Item Highlights 和 Search Terms 只写全族共有的内容。各子体自己的三样写在「变体差异表」里。
- 先分清哪些事实全族相同、哪些只属于某个子体。某个子体没有的功能，绝不能因为兄弟有就写上。

## 各模块要改什么

| 模块 | 变体族下怎么做 |
|---|---|
| 必答问题表 | 加上“这几款有什么区别、我该选哪个”这类跨变体问题；回答要用全族资料 |
| 关键词分配表 | 同一条词对不同子体去向不同时，在“去哪”里按子体注明 |
| 后台属性表 | 全族相同的填一次；各子体不同的值进变体差异表 |
| 标题 | 最要紧的变体属性（颜色、尺寸、件数）进子体标题；每个子体标题都要单独满足长度上限 |
| Item Highlights | 放不进标题的次要变体属性放这里；子体没有的功能要明写没有，或者不提 |
| 五点 | 全族共享的卖点写族级表达；本子体独有的卖点至少 1 条 |
| Search Terms | 各自埋本子体的规格词，和本子体规格冲突的词不放；只差颜色的兄弟可以相同 |
| A+ | 用对比表帮买家选型号，只比自家商品 |
| 图片 | 图 7 讲清变体怎么选；子体图片要和子体事实一致（颜色、件数） |

## 产出

交付模板的「变体差异表」：每个子体一行，填 Title、Item Highlights、Search Terms 和本子体独有的事实。检查脚本会逐行查长度，并列出每个子体的实测长度。
